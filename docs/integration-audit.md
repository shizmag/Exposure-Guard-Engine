# Factual Audit: ExposureGuard Engine & Integrations Implementation

This document provides a factual, evidence-based review of the ExposureGuard Engine integration subsystem as of commit `6eb9a19`. Each assertion and claim from the previous implementation is reviewed and categorized into one of four verified statuses:
- **verified**: Proven by deterministic code, automated tests, and runtime verification.
- **partially verified**: Implemented partially, but with missing edge cases, unsafe assumptions, or lack of determinism.
- **false**: Directly contradicted by implementation reality or security constraints.
- **not tested**: Claimed in documentation or reports, but lacking any automated test or proof.

## Detailed Findings

### 1. Integration Fixtures: `false`
- **Previous Claim**: Testdata directories contain verified upstream output fixtures.
- **Reality**:
  - `integrations/subfinder/testdata/subfinder_result.jsonl`: 3 lines of handcrafted JSON with mock data.
  - `integrations/httpx/testdata/httpx_result.jsonl`: 2 lines of synthetic JSON with `timestamp: "2026-10-06..."`.
  - `integrations/katana/testdata/katana_result.jsonl`: 4 lines of synthetic JSON.
  - `integrations/nuclei/testdata/nuclei_result.jsonl`: 3 lines of synthetic JSON.
- **Gaps**:
  - No fixtures generated by executing pinned binaries (`subfinder v2.16.0`, `httpx v1.12.0`, `katana v1.8.0`, `nuclei v3.11.1`).
  - No edge case fixtures: empty output, truncated JSON line, unexpected new fields in future versions, multi-record batches.
  - Parser resilience against unknown fields was not tested.

### 2. Docker Network Isolation & Cloud Metadata: `false`
- **Previous Claim**: Docker execution prevents cloud metadata access and secures scanning.
- **Reality**:
  - ExposureGuard Go engine implements `SafeDialer` with IP blocklists in `pkg/netguard`.
  - However, external subprocesses (`httpx`, `katana`, `nuclei`) use their own independent network stacks and DNS resolvers. They do **not** route traffic through Go `SafeDialer`.
  - Standard Docker bridge networks route outbound traffic through the host gateway. Unless the host or container network namespace enforces iptables/nftables egress filtering, external binaries can connect to link-local (`169.254.169.254`) or internal subnets if accessible from the host.
  - Claiming Docker alone solves metadata/SSRF risks without network-level egress enforcement is false and hazardous.

### 3. Version Pinning: `verified`
- **Previous Claim**: Tools and template versions are cryptographically pinned.
- **Reality**:
  - Checked against official ProjectDiscovery releases:
    - `subfinder v2.16.0`: all 4 platform SHA-256 match `subfinder_2.16.0_checksums.txt`.
    - `httpx v1.12.0`: all 4 platform SHA-256 match `httpx_1.12.0_checksums.txt`.
    - `katana v1.8.0`: all 4 platform SHA-256 match `katana-1.8.0-checksums.txt`.
    - `nuclei v3.11.1`: all 4 platform SHA-256 match `nuclei_3.11.1_checksums.txt`.
    - `nuclei-templates v10.5.0`: SHA-256 matches `nuclei-templates-10.5.0_checksums.txt`.
  - Verification confirmed: real releases exist and hashes match.

### 4. Single Source of Truth Manifest: `false`
- **Previous Claim**: `tools.lock.json` is the single source of truth across all platforms.
- **Reality**:
  - Repository contained two identical files: `/tools.lock.json` and `/pkg/integration/tools.lock.json`.
  - Go's `//go:embed` does not allow referencing parent directories (`../tools.lock.json`).
  - The duplicate file could drift undetected whenever `/tools.lock.json` is updated.
  - No drift test existed in CI.

### 5. Public vs Owned Mode CLI Policy: `false`
- **Previous Claim**: Strict policy prevents active tools from running in public mode.
- **Reality**:
  - Running `exposureguard scan example.com --integrations subfinder,httpx` in default `public` mode silently filtered out `httpx` inside `shouldRunIntegration` without any notice, warning, or error.
  - Users explicitly requesting active tools received no indication that the tool was disallowed by policy.

### 6. Process Cancellation & Lifecycle: `partially verified`
- **Previous Claim**: centralized `Runner` owns process supervision, bounded stdout/stderr, timeouts, process group signal propagation (`SIGTERM` -> grace period -> `SIGKILL`).
- **Reality**:
  - Code in `pkg/integration/process.go` and `process_unix.go` does correctly set `Setpgid: true` and kills negative PID with `SIGTERM` followed by `SIGKILL`.
  - `boundedBuffer` and bounded stdout files prevent memory exhaustion.
  - However, context cancellation prior to timeout lacked dedicated unit tests.

### 7. Snapshot Deduplication: `verified`
- **Previous Claim**: Deterministic deduplication and sorting of Assets, Observations, and Findings.
- **Reality**:
  - `pkg/snapshot/build.go` computes SHA-256 based IDs (`ComputeAssetID`, `ComputeObservationID`, `ComputeFindingID`).
  - Merge strategies correctly concatenate sources and merge attributes.
  - Deterministic sort orders are implemented and tested in `pkg/snapshot/snapshot_test.go`.

### 8. Nuclei Profile Safety: `partially verified`
- **Previous Claim**: Curated defensive profile prevents intrusive testing, DDoS, brute force, or vulnerability exploitation.
- **Reality**:
  - Relied entirely on CLI flags `-tags` and `-etags`.
  - Upstream template tags are mutable, community-contributed, and not guaranteed to prevent intrusive requests.
  - Does not validate template protocols (e.g. raw TCP, code, javascript, headless).
  - Normalization unconditionally degraded `critical` upstream severity to `high`, discarding original severity.
  - Finding evidence did not preserve source template IDs or ruleset versions.

### 9. Local vs Docker Parity: `not tested`
- **Previous Claim**: Parity between local and Docker execution ensures bitwise-identical snapshot structures.
- **Reality**:
  - Zero tests existed comparing snapshots generated by local binary vs Docker container.
  - The claim was aspirational and unverified.

### 10. "Single Static Binary" Claim: `false`
- **Previous Claim**: Single static binary CLI.
- **Reality**:
  - Core native scanner is a static Go binary.
  - Enhanced profiles (`standard`, `deep`) require external binaries (`subfinder`, `httpx`, `katana`, `nuclei`) and template directories.
  - Calling it a "single static binary" without qualifying that integrations require external toolchains is misleading.

### 11. Owned Mode Semantics: `false`
- **Previous Claim**: `deep` profile "requires ownership verification".
- **Reality**:
  - Standalone CLI cannot perform cryptographic, DNS, or HTTP ownership verification.
  - Specifying `--mode owned` is merely a caller declaration of authorization.
  - Documentation failed to make clear that ExposureGuard Cloud must perform strict pre-flight verification before dispatching `mode=owned` to engine workers.

## Action Plan for Hardening

1. **Manifest Unification**: Enforce `/tools.lock.json` as canonical root manifest. Embed via code generation or build step with an automated drift test in CI.
2. **Integration Fixtures**: Generate authentic machine-readable outputs by executing pinned binaries against controlled targets. Add comprehensive test cases (valid, multiple, empty, malformed, unexpected fields).
3. **CLI Policy Alignment**: When an integration forbidden by the active mode is explicitly requested, fail with an explicit `ExitCodeError` and policy guidance.
4. **Curated Nuclei Ruleset**: Create `profiles/nuclei/v1/` with exact allowed template IDs. Validate against headless, code, js, OOB, and raw network actions. Preserve `source_severity` and `normalized_severity`.
5. **Controlled Local E2E Fixture**: Create a deterministic synthetic web server. Run actual external binaries end-to-end to generate canonical snapshots and verify State A vs State B diff.
6. **Local vs Docker Parity Test**: Automated test ensuring semantic equality between local and Docker execution.
7. **Egress Security Hardening**: Document container egress isolation requirements, clarify external process network model in `docs/deployment-security.md`, and add regression tests for blocked destinations.
8. **Documentation Corrections**: Correct README regarding single static binary, versioned Docker tags, and realistic security guarantees.
